Что это

Сайт добавил к Part 22 тезис: с Opus 5 можно смелее полагаться на суждение модели при работе с противоречивым контекстом, потому что модель якобы лучше держит prompt injection. Повод — запуск Opus 5 и заявление о его устойчивости к таким атакам. Раньше эту проблему закрывали в первую очередь режимами разрешений: Claude Code спрашивал перед рискованными действиями, а ты вручную решал, можно ли их пускать. Auto Mode убирает часть таких остановок, но подставляет между агентом и действием отдельный защитный классификатор. Сам добавленный совет не даёт настройки Opus 5 и не делает Auto Mode автоматически безопасным.

Как работает

Prompt injection — это вредная инструкция, спрятанная в файле, странице или результате инструмента, которая пытается увести агента от твоей задачи. В Auto Mode Claude Code не просто исполняет всё подряд: перед рискованным действием отдельный классификатор проверяет, не выходит ли оно за границы запроса, не лезет ли в незнакомую инфраструктуру и не похоже ли на реакцию на враждебный текст. Классификатор видит запросы, вызовы инструментов и содержимое CLAUDE.md, но результаты инструментов из него вырезаются; отдельно серверная проверка сканирует эти результаты до показа модели. Локальные чтения и правки в рабочей папке обычно проходят без этого дополнительного шага, а внешние, разрушительные и сетевые операции доходят до классификатора. Это отличается от acceptEdits: тот автоматически принимает правки файлов и часть обычных файловых операций, а Auto Mode пытается пропускать более широкий набор действий под фоновым контролем. Важная граница: классификатор работает на серверно выбранной модели и не зависит от выбранного через /model основного агента, поэтому связка именно Opus 5 плюс Auto Mode не следует из механики сама по себе. Auto Mode остаётся исследовательским превью и не заменяет проверку чувствительных операций.

Пример

Для одного сеанса из каталога проекта запусти claude --permission-mode auto. Если режим доступен для твоего аккаунта, Claude Code перейдёт в Auto Mode и будет проверять опасные действия в фоне вместо запроса подтверждения на каждое из них. Чтобы сделать режим стартовым для проекта, в .claude/settings.json можно указать

{ "permissions": { "defaultMode": "auto" } }

Как проверить

После запуска в строке состояния CLI должен быть выбран Auto Mode; если классификатор заблокирует действие, появится уведомление, а причина попадёт в /permissions в Recently denied. Проверить заявленные сайтом почти нулевые успехи атак этим способом нельзя: материала с воспроизводимым тестом нет.

Где споткнёшься

  • Auto Mode доступен не всем тарифам и провайдерам; в текущей официальной странице среди поддерживаемых моделей Opus 5 не указан, так что его совместимость с этим режимом не подтверждена.
  • Auto Mode — исследовательское превью, а не гарантия защиты: для чувствительных операций всё равно нужен твой контроль.
  • Граница вроде «не деплой без меня» хранится в контексте сессии и может пропасть после compaction; для жёсткого запрета нужна deny-правило, а не фраза в чате.
  • В VS Code настройка claudeCode.initialPermissionMode не принимает auto; для старта в этом режиме документация указывает permissions.defaultMode в настройках Claude Code.

Слои достоверности

01 Boris Cherny (@bcherny) · в оригинале

Борис Черни — автор первоисточника; в его профиле указано: Claude Code @anthropicai. В загруженном фрагменте он называет Opus 5 сильной моделью для программирования и других задач и говорит, что больше всего его радует то, что это наименее подверженная prompt injection модель. Фрагмент обрывается на середине фразы после упоминания PI-оценок, поэтому точную методику, цифры и продолжение мысли из него узнать нельзя. В видимой части поста нет ни Auto Mode, ни утверждения про почти нулевой процент успешных атак.

02 дописано на сайте

Автор сайта дописал оценки про лидерство Opus 5 в нескольких бенчмарках, слои защиты из модели, PI-probes и Auto Mode, а также показатель успешности атак около 0%. Он же сделал вывод, что из-за этого можно переходить от жёстких правил к контекстному суждению модели. Это интерпретация автора сайта, а не текст загруженного фрагмента поста Бориса.

03 code.claude.com · документация

Официальная документация подтверждает саму механику защиты Claude Code: разрешения, серверную проверку результатов инструментов и отдельный классификатор Auto Mode, который не читает результаты инструментов. Она прямо предупреждает, что Auto Mode не гарантирует безопасность и не заменяет проверку чувствительных действий. Текущая страница требований Auto Mode перечисляет Sonnet 4.6, Opus 4.6 и Opus 4.7, но не Opus 5, поэтому совместимость Opus 5 с этим режимом подтвердить по официальной документации не удалось.

04 вывод наблюдателя

Забирать отсюда можно только практический вывод про Auto Mode: он добавляет реальный защитный слой, когда надо дать Claude Code долго работать в знакомой локальной задаче. Считать, что Opus 5 теперь позволяет расслабить правила доступа, нельзя: сайт не показал методику и цифры, а документация не обещает полной защиты. Для соло-разработки это повод аккуратно проверить Auto Mode, а не перестраивать свои правила вокруг рекламного тезиса.
